# DejaVu API v1

This section is the technical reference for the DejaVu API. Endpoints are documented from `api-reference/openapi.json`.

## Authentication

Most endpoints accept an API key in the `x-api-key` header or a Bearer token in `Authorization`.

```http
x-api-key: pk_YOUR_KEY
```

or:

```http
Authorization: Bearer YOUR_KEY
```

API keys must not be placed in the URL. The `?api_key=` form is not supported.

## Response convention

Endpoints using the standard envelope return an object containing `success` and, depending on the operation, `data`, `pagination`, or `user`.

HTTP status codes remain the source of truth for determining whether a request succeeded.

## Playground

The OpenAPI reference provides an interactive playground when the endpoint is compatible with it. You can enter authentication, parameters, and a request body, then inspect the real response.

For advanced DejaVu-specific tests, including scenarios requiring user context or internal operations, you can also use the administrator playground available in DejaVu.

<Warning>
Never share an `sk_` key in a client application or publicly distributed code.
</Warning>
